# Правила d20

## Источники истины, по порядку

1. `docs/rules/<подсистема>.md` — наши переработки.
2. SRD 5.2 (CC-BY-4.0, ADR-0018) — всё, что не переработано.
3. Если правило не описано ни там, ни там, — **спроси**, не придумывай.

Никакого контента вне SRD (монстры, заклинания, сеттинги, названия D&D). См. `docs/LICENSING.md`.

## Где что лежит

- Механика — код: `core/rules/` (броски, проверки, модификаторы, состояния), `core/combat/` (`CombatState`, ход, команды, результаты, ИИ), `core/grid/` (сетка, A*, LoS, зоны).
- Контент — данные ruleset/модуля: классы, расы, черты, заклинания, предметы, существа.
- Формулы в данных (`"1d8 + STR"`, `"8 + PROF + INT"`) — через `core/rules/formula.gd` (белый список: кости `NdM`, `+ - * /` с делением вниз, `min`, `max`, переменные). Не используй `Expression`.

## Как устроен ход

1. Представление или ИИ создаёт команду (`MoveCommand`, `AttackCommand`, …).
2. `command.validate(state)` → список причин отказа (пустой = можно).
3. `command.apply(state, rng)` → список результатов (`AttackRolled`, `DamageDealt`, `ConditionApplied`, …) и изменённое состояние.
4. Представление анимирует результаты. Оно не меняет состояние само.

ИИ противников использует те же команды и ту же валидацию.

## Инварианты

- Только `int`. Только `Rng` (через параметр, не глобально). Без времени. Словари — по отсортированным ключам.
- Каждый бросок попадает в результаты (для лога боя и реплеев).
- Порядок применения модификаторов фиксирован и описан в `docs/rules/`.

## Чеклист изменения механики

- [ ] Правило описано в `docs/rules/` (новое или изменённое).
- [ ] Unit-тесты, включая граничные случаи (см. скил `testing`).
- [ ] Golden-реплей добавлен или обновлён с объяснением.
- [ ] Если меняется формат данных ruleset — обновлены схема в `schemas/` и тестовые фикстуры.
- [ ] Если изменение противоречит SPEC/ADR — сначала скил `record-decision`.
