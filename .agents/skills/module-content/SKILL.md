# Модули контента

Источник истины по формату — `docs/SPEC.md` §7–8 и ADR-0003, ADR-0005.

## Правила

- Модуль — папка `modules/<id>/` (при разработке) или zip с той же структурой.
- Только JSON + PNG/OGG/GLB. **Никаких `.tscn`, `.tres`, `.res`, `.gd`** в модулях.
- Все ссылки — по id (`[a-z0-9_.]+`), уникальным внутри своего типа. Ссылка на объект в области — `<area_id>.<object_id>`.
- Пути ассетов — относительные от корня модуля, только прямые слэши, без `..`.
- Все строки, видимые игроку, — ключи локализации (`"locale:dialog.elder.greeting"`), тексты — в `locales/ru.json` и `locales/en.json`.
- Каждый файл соответствует схеме в `schemas/`. После правки контента запусти валидацию (тест `tests/integration/test_modules_valid.gd` проверяет все модули в `modules/`).

## События

```json
{ "id": "intro_once", "on": "trigger_entered", "source": "village.gate_trigger",
  "if": [ { "flag": "intro_done", "eq": false } ],
  "then": [ { "action": "start_dialog", "dialog": "elder_intro" },
            { "action": "set_flag", "flag": "intro_done", "value": true } ] }
```

Используй только триггеры, условия и действия из схемы `schemas/event.schema.json` и справочника `docs/events.md` (появятся на этапе 2). Не придумывай новые действия в данных.

### Добавить новый тип действия/условия/триггера

1. Убедись, что его нельзя выразить существующими.
2. Реализация в `core/` через команды ядра — не через прямой доступ к нодам.
3. Схема `schemas/event.schema.json`.
4. Справочник `docs/events.md`.
5. Тест, включая сохранение/загрузку, если действие меняет состояние.
6. Если меняется смысл существующего — это ломающее изменение: повысь `api_version` и обсуди.

## Безопасность загрузки

Модуль — недоверенные данные: проверяй схему, ссылки, пути (zip-slip), размеры и количество файлов, лимиты GLB. Ошибка загрузки — понятное сообщение игроку, не падение.
