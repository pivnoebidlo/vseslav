# AGENTS.md

Инструкции для всех AI-агентов (Claude Code, opencode, Codex, Cursor и др.). Это единственный источник инструкций: `CLAUDE.md` только импортирует этот файл.

## Проект

Vseslav (рабочее название) — однопользовательская 3D RPG на Руси времён Всеслава Полоцкого, XI век (летописная хроника с фольклорной нечистью и влиянием игрока на историю), для Windows/Linux/macOS на **Godot 4.x** и **строго типизированном GDScript**. Realtime-исследование, пошаговый бой на квадратной сетке по переработанным правилам d20 (SRD 5.x, CC-BY-4.0). Весь контент — в модулях (JSON + ассеты). Редактор приключений: сначала плагин Godot, потом встроенный в игру.

Перед работой прочитай документ, относящийся к задаче:

- [docs/GAME_DESIGN.md](docs/GAME_DESIGN.md) — что за игра: сеттинг (Русь XI века, эпоха Всеслава), тон, классы, бестиарий. Читай перед любым контентом, текстами и названиями.
- [docs/SPEC.md](docs/SPEC.md) — ТЗ, источник истины.
- [docs/adr/](docs/adr/) — принятые решения и их причины.
- [docs/ROADMAP.md](docs/ROADMAP.md) — текущий этап и критерии приёмки. **Не делай работу будущих этапов**, если об этом не просили.
- [docs/OPEN_QUESTIONS.md](docs/OPEN_QUESTIONS.md) — нерешённое. Если задача упирается в открытый вопрос — остановись и спроси, не решай сам.
- [docs/LICENSING.md](docs/LICENSING.md) — перед добавлением любого внешнего контента или зависимости.

## Структура

```
core/                    чистая логика: rules, combat, grid, rng, state, save, modules — без Node/SceneTree
game/                    сцены, ноды, UI, камера, ввод → команды ядра
editor/                  общая логика редактора (модель, команды, undo/redo, валидация) — без API редактора Godot
addons/vseslav_editor/   EditorPlugin (только UI-обвязка)
addons/gut/              фреймворк тестов (сторонний, не править)
modules/                 контент: базовая кампания, тестовые модули
schemas/                 JSON Schema для файлов модуля и сейвов
art/                     исходники ассетов (.blend и т. п.), не попадают в модули
tests/unit|integration|golden
tools/                   скрипты для разработки и CI
docs/                    ТЗ, ADR, правила (docs/rules/)
```

Зависимости: `game → core`, `editor → core`, `addons/vseslav_editor → editor, core`. **`core/` не импортирует ничего из других папок и не использует `Node`, `SceneTree`, `Input`, рендер.**

## Команды

```sh
tools/test.sh            # все тесты GUT headless
tools/test.sh tests/unit # подмножество
tools/lint.sh            # gdlint + gdformat --check
gdformat <files>         # форматирование
tools/record_golden.sh   # перезапись golden-реплея — только при намеренном изменении правил
tools/export.sh [macOS|Windows|Linux]   # релизные сборки в build/

# Запуск игры и дымовая проверка без участия человека:
godot --path .                                   # обычный запуск
godot --path . -- --autoplay --seed=42 --screenshot=/путь/shot.png   # ИИ за обе стороны, снимок и выход
```

Godot **4.7.2** ([ADR-0015](docs/adr/0015-toolchain-versions.md)) должен быть в `PATH` как `godot` или задан через переменную `GODOT`. Перед тем как сказать «готово», запусти тесты и линт и приведи результат. Если запустить не получилось — так и скажи.

## Жёсткие правила

1. **Godot 4, не Godot 3.** Сверяйся со скилом `godot-gdscript`: никаких `yield`, `export var`, `onready var`, `KinematicBody`, `instance()`, `connect("signal", self, "method")`.
2. **Типизация везде.** Предупреждения о нетипизированном/небезопасном коде — ошибки проекта; не отключай их и не обходи через `Variant`/`@warning_ignore` без объяснения в комментарии.
3. **Детерминизм в `core/`:** случайность только через `Rng`; без `randi()/randf()/randomize()/shuffle()/pick_random()`; без `float` в правилах; без времени; обход словарей по отсортированным ключам.
4. **Контент — в данных.** Никаких хардкодов классов, предметов, монстров, диалогов в коде. Сцены `.tscn` не являются форматом модуля и не сохраняются во время игры.
5. **Никакого исполняемого кода из модулей:** не загружай GDScript из `user://`, не используй `Expression` для данных модулей.
6. **Тесты обязательны** для любого изменения в `core/` и `editor/`. Исправление бага начинается с падающего теста.
7. **Решения фиксируются.** Если изменение противоречит SPEC/ADR или вводит новое архитектурное решение, новую зависимость, новый формат — сначала спроси, затем оформи ADR (скил `record-decision`) и обнови SPEC в том же изменении.
8. **Не трогай:** `.godot/`, `addons/gut/`, `*.import`, сгенерированные файлы; ассеты без лицензии.
9. **Не выдумывай API Godot.** Если не уверен, что метод/класс существует в нашей версии, — проверь по документации или исходникам, а не по памяти.

## Стиль

- Идентификаторы, имена файлов, ключи JSON — английский, `snake_case` для файлов/переменных/функций, `PascalCase` для классов (`class_name`), `SCREAMING_SNAKE_CASE` для констант.
- Комментарии и документация — по-русски. Строки интерфейса — только через ключи локализации.
- Один класс — один файл; `class_name` у всех классов ядра.
- Коммиты — Conventional Commits (`feat:`, `fix:`, `test:`, `docs:`, `refactor:`, `chore:`), описание по-русски, одно логическое изменение на коммит.
- Небольшие изменения. Если задача требует правки больше ~10 файлов — сначала предложи план.
