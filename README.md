# Vseslav (рабочее название)

Однопользовательская 3D RPG на Руси времён Всеслава Полоцкого (XI век) — летописная хроника, в которой нечисть из сказок реальна. Windows, Linux и macOS: realtime-исследование, пошаговый бой на квадратной сетке по переработанным правилам d20, собственный редактор приключений и модули контента.

Движок — Godot 4.x, язык — строго типизированный GDScript.

> Статус: этап 1, боевой срез, — код готов, идут плейтесты ([ROADMAP](docs/ROADMAP.md)). Три тестовых боя (разбойники, волки с полудницами, упыри) отрядом из шести: ратник, ловчий, волхв, тать, ярый, священник; просмотрщик моделей с ретаргетингом анимаций.

## Запуск

Клонирование:

```sh
git clone https://github.com/pivnoebidlo/vseslav.git
cd vseslav
```

Бинарные ассеты (включая `addons/gut`) хранятся в Git LFS, поэтому после клонирования репозитория необходимо их скачать:

```sh
git lfs pull
```

Если команда `git lfs` выдаёт ошибку `git: 'lfs' is not a git command`, необходимо установить [Git LFS](https://git-lfs.com/).

После клонирования репозитория (а также после добавления новых `class_name`) необходимо выполнить импорт `class_name` и ассетов:

```sh
godot --headless --import
```

В отличие от открытия проекта в редакторе, `godot --path .` сам не выполняет импорт, а содержимое .godot/ в репозитории не хранится. Скрипты в `tools/` делают импорт сами, для них выполнять импорт нет необходимости.

Запуск тестового боя и другие задачи:

```sh
godot --path .                 # главное меню: «Продолжить», «Новая игра», «Редактор сюжета» (docs/editor.md) — карта с деревней, лесом (разбойники) и погостом (полудница); ЛКМ — идти/говорить/атаковать, Tab или портрет — выбор героя, G — сетка, Q/E — поворот, колесо — масштаб, F5/F9 — сохранить/загрузить, Esc — меню и опции (журнал боя); бой начинается прямо на карте; слева кнопки «Вещи» (I), «Журнал» (J), «Торг» (T), «Отдых» (R)
tools/fetch_sample_models.sh   # скачать образцы моделей в пользовательскую папку
tools/import_kaykit_props.sh   # пересобрать модели окружения (KayKit, CC0) в modules/base/props
godot --path . -- --smoke --screenshot=/tmp/s.png # дымовая проверка: бой на карте, ИИ за обе стороны, снимок и выход
godot --path . res://game/spikes/model_viewer.tscn   # просмотр моделей и ретаргетинг анимаций
tools/test.sh                  # тесты
tools/lint.sh                  # линтер
tools/export.sh                # сборки для macOS, Windows, Linux в build/
```

Если исполняемый файл Godot Engine имеет имя, отличное от `godot`, а также если он недоступен в `PATH`, то можно переопределить путь к нему через переменную GODOT — скрипты в tools используют эту переменную при её наличии. Например:

```sh
export GODOT=/home/user/Godot_v4.7.2/Godot_v4.7.2-stable_linux.x86_64
tools/test.sh
```

## Сборка

Для сборки исполняемых файлов необходимо установить шаблоны экспорта (Export Templates) под нужные платформы и архитектуры. Шаблоны можно скачать из редактора Godot в меню **Editor - Manage Export Templates**. Можно также скачать
полный архив шаблонов с сайта Godot и импортировать в том же разделе. После этого можно выполнить скрипт `tools/export.sh` либо собрать сборку под конкретную архитектуру вручную из редактора в меню **Editor - Export**.

## Как мы работаем

1. Задача берётся из текущего этапа ROADMAP.
2. Код пишет агент; он следует [AGENTS.md](AGENTS.md) и скилам в `.agents/skills/`.
3. Любое изменение проходит тесты и линт (`tools/test.sh`, `tools/lint.sh`) и ревью человеком.
4. Новое решение → ADR + обновление SPEC в том же PR.

## Требования для разработки

- Godot 4.7.2 ([ADR-0015](docs/adr/0015-toolchain-versions.md)), доступный как `godot` или через `GODOT=/путь/к/godot`, и шаблоны экспорта той же версии (для сборок). На macOS: `brew install --cask godot`.
- gdtoolkit 4.x: `brew install gdtoolkit` или `pip install "gdtoolkit==4.*"`.
- Git LFS.
- Blender — для работы с моделями.
