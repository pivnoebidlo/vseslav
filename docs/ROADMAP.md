# Дорожная карта

Каждый этап заканчивается тем, во что можно поиграть или что можно показать. Этап считается закрытым, когда выполнены **все** критерии приёмки, а тесты и линт зелёные в CI.

Сроки — ориентиры, не обязательства.

---

## Этап 0 — Каркас и спайки (1–2 недели)

Цель — проверить самые рискованные технические гипотезы до того, как на них завяжется архитектура.

- [x] Godot-проект по структуре из [SPEC §6.1](SPEC.md#61-слои), версия движка закреплена ([ADR-0015](adr/0015-toolchain-versions.md)).
- [x] GUT, `tools/test.sh`, `tools/lint.sh`.
- [ ] CI (тесты + линт на PR) — после выбора хостинга ([OPEN_QUESTIONS](OPEN_QUESTIONS.md) №9).
- [x] Предупреждения о нетипизированном и небезопасном коде включены как ошибки.
- [ ] Спайк: загрузка GLB со скелетом и анимацией **во время игры** из папки вне `res://`.
- [ ] Спайк: ретаргетинг одной анимации (Quaternius/Mixamo) на модель с другим скелетом через `SkeletonProfileHumanoid`.
- [x] Спайк: A* на сетке с уровнями высоты, детерминированный (одинаковый путь при повторных запусках).
- [x] Спайк: `Rng` + бросок атаки + сохранение/загрузка состояния → тот же результат следующего броска (плюс тестовая арена с пошаговым боем, ИИ и golden-реплеем).
- [ ] Экспорт под Windows, Linux, macOS запускается (подпись macOS — позже).

**Готово, когда:** все спайки работают, выводы записаны в ADR (подтверждены или исправлены).

## Этап 1 — Боевой срез (3–6 недель)

Цель — пошаговый бой, в который интересно играть.

- [ ] Ядро правил: характеристики, модификаторы, проверки, атаки, урон, спасброски, преимущество/помеха, 5–8 состояний.
- [ ] Экономика действий, инициатива, перемещение по сетке, атаки при отходе (реакция).
- [ ] Данные: 2–3 класса с одним путём (например, ратник-дружинник, ловчий, волхв), 2 происхождения, 10+ предметов эпохи, 4–6 видов противников (люди, звери, 1–2 нечисти с фольклорными условиями), 6–10 заговоров/способностей — механика SRD, облик свой.
- [ ] Одна тестовая арена (пока можно собранная вручную), партия из 3, противники с простым ИИ.
- [ ] UI боя: порядок хода, подсветка достижимых клеток, предпросмотр атаки (шанс, урон), лог бросков.
- [ ] Сохранение и загрузка в середине боя.
- [ ] Golden-тесты: 3+ записанных боя воспроизводятся побитово.

**Готово, когда:** команда сыграла десяток боёв и считает, что это интересно; найденные проблемы баланса записаны.

## Этап 2 — Исследование и модуль (4–6 недель)

- [ ] Формат модуля v1, JSON Schema, загрузчик и валидатор; базовая кампания — модуль.
- [ ] Область из JSON: тайлы, объекты, триггеры, переходы.
- [ ] Realtime-исследование: перемещение партии, камера, взаимодействие.
- [ ] Переход Exploration ⇄ Combat по SPEC §3.2.
- [ ] Диалоги, квесты, журнал, инвентарь.
- [ ] Декларативные события v1 (SPEC §8).
- [ ] Загрузка модуля из папки и из zip с проверками.

**Готово, когда:** вертикальный срез — деревня, диалог, квест, подземелье с двумя боями — проходится от начала до конца, всё в модуле.

## Этап 3 — Редактор A: плагин Godot (4–8 недель)

- [ ] Общая логика `editor/`: команды, undo/redo, валидация.
- [ ] Плагин: области (тайлы, слои, высоты), объекты, NPC, энкаунтеры, триггеры, инспектор.
- [ ] Редакторы диалогов, квестов, событий.
- [ ] Playtest из редактора, упаковка zip.

**Готово, когда:** вертикальный срез из этапа 2 пересобран в редакторе без ручной правки JSON.

## Этап 4 — Конвейер контента и пользовательские модели

- [ ] Процесс AI/Blender → GLB описан и проверен на 5+ моделях (ретопология, UV, риг, LOD).
- [ ] Реестр ассетов модуля, лимиты и валидация, понятные ошибки.
- [ ] Импорт пользовательской модели персонажа в игре с ретаргетингом анимаций.

## Этап 5 — Редактор B: встроенный в игру

- [ ] Функционал редактора A на `Control`-нодах в экспортированной игре, поверх `editor/` и `core/`.
- [ ] Импорт/экспорт модулей zip из меню игры.

## Этап 6 — Lua в песочнице

- [ ] Выбор биндинга, сборки под все платформы.
- [ ] Песочница и лимиты по SPEC §8, тесты на атакующие сценарии.
- [ ] Lua API v1 поверх тех же команд ядра, что и декларативные события; справочник API генерируется.
- [ ] Права в манифесте, экран разрешений при установке.

## Потом

Репозиторий модулей (статический индекс + хеши + подписи), Steam/Workshop, Steam Deck, подпись и нотаризация macOS в CI, доступность.
