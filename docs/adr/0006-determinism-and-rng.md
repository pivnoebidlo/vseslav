# ADR-0006: Детерминизм ядра и RNG

- Статус: Принято
- Дата: 2026-11-18

## Контекст

Сохранение в середине боя, воспроизведение багов, golden-тесты, честные перебросы.

## Решение

- В `core/` единственный источник случайности — класс `Rng` (обёртка над `RandomNumberGenerator` с явными `seed` и `state`, которые сохраняются в сейв). `randi()`, `randf()`, `randi_range()`, `randomize()`, `Array.shuffle()`, `Array.pick_random()` в `core/` запрещены.
- Арифметика правил — только `int`.
- Итерация по `Dictionary` в логике, влияющей на результат, — по `keys()` после `sort()`.
- Время (`Time`, `OS.get_ticks_*`) в логике ядра запрещено.
- Golden-тесты: seed + последовательность команд → ожидаемое состояние. Набор golden-реплеев прогоняется в CI.
- Если обновление Godot меняет поведение `RandomNumberGenerator`, golden-тесты это поймают; тогда `Rng` переводится на собственную реализацию (PCG32) отдельным ADR.

## Последствия

- Realtime-исследование может быть недетерминированным, но любые броски там идут через `Rng`.
