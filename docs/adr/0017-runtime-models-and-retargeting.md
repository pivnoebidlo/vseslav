# ADR-0017: Загрузка моделей и ретаргетинг во время игры

- Статус: Принято
- Дата: 2026-11-19
- Уточняет [ADR-0009](0009-assets-pipeline.md); итог спайка этапа 0

## Контекст

Модели персонажей будут приходить из разных источников (KayKit/Quaternius, Blender, AI-генераторы с авториггингом, Mixamo, модели игроков). У них разные имена костей, позы покоя (T-поза, A-поза), оси костей и пропорции. Анимации хочется делать (или брать) один раз и проигрывать на любой гуманоидной модели — во время игры, без импорта в редакторе.

## Решение

1. **Загрузка** — `CharacterLoader` (`game/characters/`): только `.glb`; проверка сигнатуры и размера до разбора; `GLTFDocument.append_from_buffer` с пустым `base_path` (внешние ссылки не разрешаются); лимиты из [SPEC §11](../SPEC.md#11-ассеты-и-модели) проверяются по `GLTFState` до создания сцены. Ошибки — ключи локализации, без падений.
2. **Распознавание рига** — профили в JSON (`game/characters/rigs/*.json`: KayKit, Mixamo, уже-гуманоидные имена). Новый источник моделей = новый JSON-профиль, без кода.
3. **Переименование костей** в имена `SkeletonProfileHumanoid` выполняется в `GLTFState` **до** `generate_scene()` — кости и дорожки анимаций остаются согласованными. Нераспознанный риг загружается с предупреждением, но без ретаргетинга.
4. **Ретаргетинг** — собственный `HumanoidRetarget`: невидимый источник с `AnimationPlayer` внутри модели цели; после каждого обновления источника позы записываются в скелет цели по формуле «Δисточника × выравнивание поз покоя × покой цели». Длины костей — свои, смещение таза масштабируется по высоте таза.

## Рассмотренные варианты

- **`RetargetModifier3D`, локальный режим** — переносит разницу поз покоя: у модели в A-позе при T-позе источника руки «задираются» на разницу поз (в тесте — 60°).
- **`RetargetModifier3D`, глобальный режим** — копирует и позиции костей: модель получает пропорции источника (таз цели на высоте источника); флаг `enable` и `motion_scale` на это не влияют (Godot 4.7.2).
- **Собственный `SkeletonModifier3D`** — в Godot 4.3+ результат модификатора временный (только для отрисовки), поза для логики и тестов не меняется.
- **Ретаргетинг при импорте в редакторе (BoneMap)** — недоступен в экспортированной игре и для моделей игроков.

## Последствия

- Тест `tests/integration/test_character_loading.gd` проверяет на синтетическом риге (имена Mixamo, рост ×1.3, оси повёрнуты на 70°, A-поза) совпадение направлений костей и сохранение роста; без сторонних ассетов.
- Скручивание вокруг оси кости (twist) не выравнивается — проверить на реальных моделях от AI-генераторов на этапе 4.
- Покачивание таза переносится масштабированно; корневое движение (root motion) пока не используется.
- При обновлении Godot стоит перепроверить `RetargetModifier3D`: если его поведение исправят, можно вернуться к встроенному.
