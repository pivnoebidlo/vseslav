# ADR-0023: Реакции персонажей игрока — вопрос в момент срабатывания

- Статус: Принято
- Дата: 2026-11-21
- Участники: команда (решение пользователя в сессии с агентом: «спрашивать в момент срабатывания»)

## Контекст

Реакции (удар вдогонку при отходе, прикрытие щитом — черта `protection`) срабатывали автоматически посреди чужого хода. Игрок должен решать сам, когда реакция возможна. Команды ядра атомарны: `validate` → `apply` → события; сохранения и golden-реплеи держатся на том, что состояние между командами полное и детерминированное.

## Решение

- Команда несёт **ответы игрока на реакции** — `reactions: Array[bool]`, по порядку возникновения вопросов. В записи команды поле есть, только если ответы были.
- Ядро при каждом поводе для реакции персонажа игрока (`player = true`) берёт следующий ответ из команды; если ответов не хватило — реакция срабатывает (как раньше). Каждый вопрос записывается в `CombatState.reactions` (`ReactionLog`) (не сохраняется): кто, какая реакция, против кого, отвечен ли.
- Интерфейс перед применением команды прогоняет её на копии состояния (`to_dict` / `from_dict`). Если встретился неотвеченный вопрос — бой ждёт ответа игрока, ответ дописывается в команду, прогон повторяется. Когда вопросов без ответа нет — команда применяется к настоящему состоянию.
- Реакции участников ИИ (и персонажей игрока в режиме `--autoplay`) решает правило по умолчанию — срабатывать.
- Подсказки игроку и ИИ (предпросмотр) по-прежнему считают, что защитник прикроет.

## Рассмотренные варианты

- Переключатели «всегда / никогда» на персонаже — проще, но нельзя решать по ситуации.
- Пауза внутри команды с сохранением недоделанного хода — нужен возобновляемый ход ядра, а сохранения и реплеи пришлось бы учить середине команды.

## Последствия

- Ядро остаётся детерминированным, сохранения — только между командами; команда с ответами воспроизводится побитово, старые golden-реплеи (без ответов) не меняются.
- Пробный прогон стоит одного копирования состояния на команду в интерактивном режиме — копейки для боя на 10 участников.
- Будущие реакции (заговоры-реакции и т. п.) добавляются вызовом `CombatState.reactions.decide` в месте срабатывания.
