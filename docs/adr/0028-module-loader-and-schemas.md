# ADR-0028: Загрузчик модулей, свой валидатор JSON Schema, замена записей зависимостей

- Статус: Принято
- Дата: 2026-11-22
- Участники: команда (решения пользователя в сессии с агентом)
- Уточняет [ADR-0003](0003-module-format-json.md)

## Контекст

ADR-0003 и SPEC §7 требуют, чтобы каждый тип файла модуля имел JSON Schema и модуль проверялся при загрузке. До сих пор игра читала файлы по жёстко заданным путям (`res://modules/base/rules`, `modules/spike/arenas`), манифест и зависимости не читались, схем не было. В Godot нет валидатора JSON Schema, а сторонние зависимости в ядре нежелательны. Нужно было решить: как проверять файлы, что делать при совпадении id между модулями и что делать с модулем, в котором есть ошибки.

## Решение

- **Схемы — единственное описание формата**: `schemas/*.schema.json` (JSON Schema 2020-12), общие определения — `common.schema.json`. По ним проверяет игра, подсказывает редактор кода, строит формы будущий редактор приключений.
- **Свой валидатор подмножества** — `core/modules/json_schema.gd`. Поддержано: `type`, `properties`, `required`, `additionalProperties`, `propertyNames`, `items`, `minItems`/`maxItems`, `enum`, `const`, `pattern`, `minLength`/`maxLength`, `minimum`/`maximum`, `anyOf`, `$ref` (внутри схемы и на другую схему). Любое другое ключевое слово в схеме — ошибка (тест `test_modules_valid`). Перечисления в схемах сверяются тестом с константами кода.
- **Строгость**: у записей `additionalProperties: false` — опечатка в имени поля — ошибка, а не тихо проигнорированное поле. Комментарий автора — поле `_comment` в корне файла.
- **Поиск модулей**: подпапки `res://modules` и `user://modules`, в которых есть `module.json`. Файлы модуля: известные JSON (`module.json`, `rules/<actions|items|classes|origins|characters|creatures>.json`, `merchants.json`, `models/models.json`, `arenas/*.json`, `locales/*.json`) и ассеты `.png`, `.ogg`, `.glb`. Любой другой файл — ошибка. Имена файлов — строчная латиница, цифры, `_`. Лимиты: 2000 файлов, 4 МБ на JSON, вложенность папок 8.
- **Порядок**: зависимости загружаются раньше, иначе — по алфавиту id. Пропавшая зависимость или цикл — ошибка модуля. `format` и `api_version` новее поддерживаемых, неизвестный `ruleset` — ошибка.
- **Совпадение id**: запись модуля **целиком заменяет** запись с тем же id из его зависимости (прямой или непрямой) — так моды правят баланс. Совпадение внутри одного модуля или с независимым модулем — ошибка. Строки локализации — исключение: поздний модуль просто заменяет строку.
- **Ошибка — модуль не загружается**, вместе со всеми, кто от него зависит; остальные работают. Каждая ошибка — строка `<модуль>: <файл>: <путь в JSON>: <что не так>`, например `vseslav.base: rules/items.json: $.items[3].weight: expected number, got string`. Встроенные модули обязаны загружаться без ошибок (тест `test_modules_valid`).
- **Проверка ссылок** после сборки: правила (`RulesDb.validate`), участники арен, товары купцов, облик (персонаж или существо с таким id, файл модели есть), ключи имён (`name_key`, `title_key`, название модуля) — есть хотя бы в одном языке.
- Код: `core/modules/` — `ModuleLoader`, `ModuleManifest`, `ModuleContent`, `ModuleRefs`, `ContentOwners`, `JsonSchema`. Игра берёт данные только из `ModuleContent`.

## Рассмотренные варианты

- **Проверки вручную в коде, схемы — документация.** Проще сейчас, но схемы и код неизбежно разойдутся, а редактору нечем будет строить формы. Отклонено.
- **Сторонний валидатор (GDExtension или порт).** Новая зависимость в ядре ради небольшого подмножества стандарта. Отклонено.
- **Совпадение id всегда ошибка.** Нельзя сделать мод баланса без копии всего модуля. Отклонено.
- **Слияние полей при совпадении id.** Гибче, но непонятно, что получилось, и нельзя убрать поле. Отклонено.
- **Загружать модуль с ошибками, пропуская битые записи.** Удобнее моддерам, но возможны странные поломки в бою и в сейвах. Отклонено.

## Последствия

- Новый тип файла (области, диалоги, квесты, события — этап 2) = схема в `schemas/` + строка в `ModuleLoader` + проверка ссылок в `ModuleRefs` + тесты.
- Новое значение перечисления в коде (тип черты, вид действия) нужно добавить и в схему — иначе упадёт тест сверки.
- Если поле читается кодом, оно должно быть описано в схеме, иначе данные с ним не загрузятся.
- `schemas/` входит в экспортированную сборку (`export_presets.cfg`).
- Zip-модули, распаковка в `user://modules/<id>/<version>/` и проверка zip-slip — отдельный пункт этапа 2.
